# 文档总入口

状态：常用
维护人：项目维护
最后更新：2026-07-29

这里是项目文档的总导航。以后不要靠“翻文件夹碰运气”找文档，先从这里进。

## 我是新手，先看什么

1. [新手上手指南](beginner-guide.md)：先理解项目是干什么的、怎么启动、哪些文件不能乱动。
2. [README](../README.md)：看项目整体介绍和一键启动方式。
3. [故障排查](故障排查.md)：启动失败、数据库失败、转写失败时先查这里。

## 我要开发或修 Bug

1. [开发流程](开发.md)：日常开发、提交、推送都按这里走。
2. [前端组件开发规范](前端组件开发规范.md)：改前端页面、组件、样式前必须看。
3. [验收测试说明](验收测试/说明.md)：改完后按模块找到该跑的验收项。

## 我要确认项目规则

1. [AGENTS 规则](../AGENTS.md)：每次任务必须遵守的协作、测试、提交规则。
2. [main 直接开发流程](adr/0029-main直接开发流程.md)：为什么取消分支开发，以及现在怎么保护 main。
3. [CHANGELOG](../CHANGELOG.md)：每次改动后记录“改了什么”。

## 我要查历史决策

看 [ADR 总索引](adr/README.md)。

ADR 的大白话解释：它记录“当时为什么这么做”。代码告诉你现在怎么做，ADR 告诉你为什么不是另一种做法。

## 我要部署或排查线上

1. [部署说明](部署.md)：部署、升级、回滚。
2. [故障排查](故障排查.md)：常见错误和处理步骤。
3. [可观测性验收](验收测试/可观测性验收.md)：日志、健康接口、监控是否正常。

## 我要维护代码结构

看 [代码治理清单](代码治理清单.md)。

这份清单只记录后续重构优先级，不代表要一次性大改。每次只处理一个明确模块，改完必须跑测试和审查。

## 文档保留规则

- 常用入口文档要短，负责指路，不堆所有细节。
- ADR 原则上只新增、不删除；旧方案被取代时，新写一篇说明取代关系。
- 验收文档按模块保留，不混成一篇大杂烩。
- 行业知识文档属于业务资料，不和技术文档混合。
