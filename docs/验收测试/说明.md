# 核心链路验收

这里记录项目关键能力的可重复验收方法。自动化测试可以使用脱敏固定样本，但业务验收必须选择数据库中已经采集到的真实账号、主播和直播场次，不允许为了"通过"而补写模拟数据。

## 统一记录要求

每次验收至少记录日期、操作者、真实账号 ID、真实场次 ID、Git 提交、Trace ID、成功项、失败项和恢复结果。Cookie、Token、浏览器指纹、完整私信内容及 AI 密钥不得写入文档或截图。

常规自检入口：

```bash
make doctor
make test
make lint
make build
```

## 改动类型与必跑验收

| 如果你改了 | 至少要看哪份验收 | 为什么 |
|---|---|---|
| 账号登录、Cookie、浏览器指纹、采集任务、评论、场次补齐 | [数据采集验收](采集器验收.md) | 这些功能都依赖保存的真实抖音登录态和浏览器环境。 |
| 话术转写、FunASR、音频分片、直播中初稿、下播后终稿 | [ASR 话术验收](语音识别验收.md) | 要确认真实音频能转写、失败能恢复、旧分片不被误删。 |
| 场次详情、视频回放、时间轴、AI 复盘、证据跳转 | [场次复盘验收](复盘验收.md) | 这些页面必须保证结论能追溯到真实场次和真实证据。 |
| 知识库问答、行业知识、引用来源、AI 回答 | [知识库验收](知识库验收.md) | 要确认回答只来自真实知识切片，不能编造经营结论。 |
| 排班模板、缺场、无效场次、加场提醒 | [主播排班验收](定时任务验收.md) | 要确认真实场次只匹配一个计划班次，不能串主播或串日期。 |
| 日志、Trace ID、健康检查、Prometheus、Grafana、DataEase 观测 | [可观测性验收](可观测性验收.md) | 要确认出错时能定位，并且监控不泄露 Cookie、Token 和客户隐私。 |
| 客资同步、客资归属、DataEase 同步、后台自动任务 | [数据采集验收](采集器验收.md) + [可观测性验收](可观测性验收.md) | 客资和 DataEase 都是后台同步链路，要同时看真实数据结果和错误可追踪性。 |

如果一次改动跨多个模块，就把对应验收都跑一遍。这样做不是为了麻烦，而是为了防止“一个页面好了，另一条真实业务链断了”。
