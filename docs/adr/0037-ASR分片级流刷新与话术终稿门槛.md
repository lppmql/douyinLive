# ADR 0037：ASR 分片级流刷新与话术终稿门槛

- 日期：2026-08-02
- 状态：已采纳

## 背景

离线转写会把长直播拆成多个两分钟分片。旧实现只在整场任务开始时探测和刷新
一次回放地址，后续所有分片都复用该临时地址。真实任务因此在第 4、20 等中间
分片遇到 404、TLS 中断或零音频后，继续用同一个坏地址消耗重试次数；页面同时
把实时初稿的未知直播时长显示成 0% 完整度，并允许基于初稿生成 AI 复盘。

页面采集还有三个问题：网络监听在页面加载后才注册，可能错过首屏唯一一次
m3u8 请求；页面残留的旧直播 FLV 会覆盖真实录播地址；新地址没有真实拉流验证
就被写成 active。

## 备选方案

### 方案 A：继续只在任务开始时刷新

改动最小，但无法恢复长任务处理中途失效的临时地址，分片重试仍会无效消耗。

### 方案 B：每个分片开始前都刷新

恢复最积极，但会频繁打开企业后台页面，增加浏览器资源、接口风控和等待时间。

### 方案 C：失败特征触发刷新并断点续传

正常分片不增加开销；只有离线分片出现 404、403、410、TLS、连接中断、I/O 错误
或零音频等流来源特征时，才强制刷新并重试当前分片。

## 最终决策

采用方案 C，并同步收紧话术页面的数据可信度：

1. 大屏页面在 `goto` 前注册媒体请求监听，候选地址优先录播 m3u8，其次才使用
   页面元素或 FLV；忽略 `blob:` 和非媒体请求。候选先保存为 pending，不替换
   当前 active。
2. 浏览器 `User-Agent` 使用原始字符串，流请求同时保存来源页 `Referer`。
3. 新媒体地址必须通过 ffmpeg 真实拉流探测后，才能在同一事务中切换 active 并
   更新 `live_sessions.stream_url`；失败候选标为 error，旧 active 保持不变。
4. 离线分片遇到确定的流来源错误时强制刷新；拿到新地址后只重试失败分片，保留
   已完成分片、文本和进度。普通 ASR 引擎错误继续沿用原重试策略。
5. 页面明确区分“实时初稿”和“离线终稿”。未知直播时长显示“已转到”的真实
   时间，不伪造 0% 覆盖率；只有完整离线终稿可以生成 AI 复盘并入库。
6. 同场同时存在终稿和初稿时只展示离线终稿；没有终稿时才展示实时初稿。实时
   短片段只有与同源长片段时间区间重叠或起点误差不超过 3 秒、且原文被完整包含
   时才隐藏；离线终稿与正常重复 CTA 保留，数据库原文不修改。
7. 长直播话术按 500 段分页完整读取，避免只统计前半场。
8. 失败任务展示可执行的中文原因、恢复提示和技术详情，入口统一命名为断点重试。

## 影响范围

- 企业后台大屏流地址采集与健康探测。
- ASR Worker 离线分片重试状态机。
- 主播话术页面的数据适配、操作门槛、任务抽屉和阅读检索。
- 不修改既有数据库表，不删除历史话术或任务。

## 验收方式

1. 录播 m3u8 与旧直播 FLV 同时出现时选择录播地址，`blob:` 不参与候选。
2. 新地址拉流失败时不更新场次地址，并返回可读错误。
3. 中间分片遇到流来源错误时触发一次强制刷新，成功后从原分片继续。
4. 实时初稿不能生成 AI 复盘，离线终稿完成后按钮才可用。
5. 真实场次页面能持续接收话术、检索业务关键词并明确展示失败恢复路径。
6. 后端测试、前端类型检查、Lint、生产构建和完整项目检查通过。
