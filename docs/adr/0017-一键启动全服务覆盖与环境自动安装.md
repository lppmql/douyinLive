# ADR 0017：一键启动全服务覆盖与环境自动安装

**日期**：2026-07-25  
**状态**：已采纳  
**决策人**：lppmql

---

## 背景

`start.sh` 是项目的一键启动入口，但存在三个问题：

1. **依赖缺失无提示**：新机器缺 Python/Node/FFmpeg/pnpm 时 `start.sh` 直接报错退出，新手不知道装什么、怎么装
2. **Qdrant 被遗漏**：Qdrant 向量数据库在 `docker-compose.yml` 中没有 `profiles` 限制，但 `start.sh` 从未启动它，知识库 RAG 功能无法工作
3. **FunASR 从未启动**：FunASR 配了 `profiles: [funasr]`，需 `--profile funasr` 才能拉起，`start.sh` 只有占位符注释没有实际启动命令，导致话术转写永远失败

## 决策

修改 `start.sh`，在启动业务服务前自动完成环境自检和依赖安装，并补上 Qdrant、FunASR 两个被遗漏的服务。

### 1. 环境自检 + 自动安装

在 `start.sh` 开头加入预检步骤，按 macOS + Homebrew 体系：

| 工具 | 检测 | 缺了怎么处理 |
|------|------|-------------|
| Homebrew | `command -v brew` | 给出安装链接，退出（后面的自动安装都依赖 brew） |
| Python 3 | `command -v python3` | `brew install python@3.12` |
| Node.js | `command -v node` | `brew install node@22` |
| FFmpeg | `command -v ffmpeg` | `brew install ffmpeg` |
| pnpm | `command -v pnpm` | `npm install -g pnpm`（node 已装好后） |
| Docker | `docker info` | 无法自动装（GUI 应用），给出 Docker Desktop 下载链接，退出 |

### 2. Qdrant 随 MySQL/Redis 一起启动

- `docker compose up -d mysql redis qdrant dataease`
- 启动后用 `wait_for_http` 检查 `http://127.0.0.1:6333/health`

### 3. FunASR 在第 5 步启动

- `docker compose --profile funasr up -d funasr`
- 用 Python 检测 WebSocket 端口 10096 是否已监听（`socket.connect`）
- 超时 300 秒（首次需下载模型），容器异常退出时打印日志

## 替代方案

| 方案 | 描述 | 结论 |
|------|------|------|
| `doctor.sh` 扩展 | 在 `scripts/doctor.sh` 加自动安装逻辑，`start.sh` 调用它 | 不采用：doctor.sh 定位是纯检查（只读），加自动安装副作用太重 |
| 永远 `ASR_ALLOW_MOCK=true` | 绕过 FunASR，用模拟数据 | 不采用：用户明确拒绝（"不要绕过"） |
| FunASR 去掉 `profiles` | 跟 MySQL/Redis 一样随 `docker compose up -d` 默认启动 | 不采用：FunASR 吃 1.8GB 内存，8GB Mac 上默认启动会导致内存不足。`--profile funasr` 让用户可选 |

## 影响

- **正面**：新机器克隆项目后 `./start.sh` 一键到位，不再需要手动排查环境
- **正面**：话术转写功能可用（FunASR 终于被启动了）
- **正面**：知识库 RAG 可用（Qdrant 终于被启动了）
- **风险**：Homebrew 自动安装可能装到非用户期望的版本（如 `python@3.12`），但比新手卡住要好
