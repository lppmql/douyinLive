# ADR 0047：原生经营大屏与外部可视化监控退役

- 状态：已接受
- 日期：2026-08-30
- 决策范围：前端、后端公共接口、数据库、Docker、部署与可观测性

## 背景

项目此前同时维护外部数据大屏、指标采集服务和监控面板。它们引入独立数据库、同步宽表、只读视图、账号密钥、容器配置和 iframe 登录兼容层，资源与维护成本明显高于当前单机零食店直播复盘业务的收益。

经营人员真正需要的是留资业务数据：曝光、进入直播间、卡片点击、站内私信、确认留资、投放成本、主播表现和场次明细。这些数据已经存在于项目真实业务源表中。

## 决策

1. 经营大屏改为 SoybeanAdmin 原生页面，复用 Naive UI、ECharts、公共主播键和北京时间日期筛选，不新增前端依赖。
2. 后端提供 `/api/v1/dashboard/operations` 组合接口，一次返回总体指标、按日趋势、留资漏斗、主播排行和最近场次；旧汇总接口继续保留并同步支持公共筛选条件。
3. 删除外部大屏的 API、同步任务、同步模型、专用配置、只读视图和汇总表。迁移只删除派生数据，不删除 `live_sessions`、`comments`、`leads`、话术、复盘等真实业务源数据。
4. 删除外部指标采集与监控容器、依赖、配置和 `/metrics` 接口。继续保留 `X-Trace-ID`、结构化日志、`/health`、任务状态与 `ai_call_traces`，作为当前规模下的轻量可观测性方案。
5. 一键启动只保留 `lite` 与 `standard` 两种模式；Docker 基础服务收敛为 MySQL、Redis、Qdrant，FunASR 按 profile 启动。

## 数据与回滚边界

迁移会永久删除旧派生表和视图，并取消尚未完成的旧同步任务。由于这些对象可由真实业务源表重新计算，迁移不提供自动降级；若确需恢复旧架构，必须同时恢复迁移前数据库备份和对应 Git 版本。

执行正式迁移前应先备份 `douyin_live` 业务库。独立的旧大屏数据库、账号、运行目录、容器、镜像和数据卷在确认方案后单独清理。

历史视图若由 MySQL 高权限账号创建，旧部署只在执行本迁移时临时使用 root；迁移完成后应用必须继续使用普通数据库账号，不授予长期高权限。

## 影响

- 优点：减少三个常驻服务、两套同步链路和多组密钥，启动更快，跨机器部署更简单；大屏筛选与业务页面口径一致。
- 代价：不再提供通用拖拽式 BI、自定义 PromQL 和现成监控面板；新的经营指标需要在组合接口和原生组件中显式开发。
- 维护要求：新大屏指标必须来自真实业务表，聚合口径要有后端测试；Trace ID、健康检查和结构化日志不可随意删除。
