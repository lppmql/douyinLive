# ADR 0042：ASR 复盘解耦与新终稿自动剪辑边界

- 日期：2026-08-25
- 状态：已采纳

## 背景

ASR 任务表保留了早期“转写完成后自动评分、AI 复盘、知识库、DataEase、剪辑”的后处理字段。后来 AI 复盘改为人工生成，但 Worker 中仍残留可执行的旧后处理方法；同时，手动生成复盘会间接创建剪辑任务。数据库因此长期积压未尝试的 `pending`，界面也把 ASR 描述为“话术、AI 复盘与知识库”，容易让运营误判真实执行状态。

历史剪辑还暴露出另一个语义问题：一场任务即使 5 条成片全部渲染失败，外层批任务仍可能记为完成；字幕精确对齐降级也只保留数量，没有可复核原因。

## 决策

采用方案 A，明确四条边界：

1. ASR Worker 只负责实时初稿和离线终稿，不执行 AI 复盘。
2. AI 评分与复盘只由运营人工触发；该操作可以同步知识库和 DataEase，但不会创建剪辑任务。
3. 自动剪辑只响应部署后“新离线终稿完成”事件，并复用任务控制器按场次去重；不扫描、不回填历史场次。
4. 知识库与 DataEase 继续由各自现有后台同步机制维护，不依赖 ASR 的旧 `postprocess_status`。

剪辑在 AI 选段前检查支持 libass 的 ffmpeg、真实已完成话术、真实回放文件或流源；缺少逐字时间戳时还检查 FunASR。任一条件不足立即失败，不产生 AI 选段费用。

场次级剪辑只有 `rendered_count > 0` 才算成功。局部渲染失败与字幕降级分别记录数量；字幕降级原因写入任务结果和成片 `qc_json`，供人工复核。

## 数据兼容

保留 `asr_tasks.postprocess_*` 字段和历史已完成、已失败记录，避免破坏既有接口与审计记录。迁移 `e6f7a8b9c0d1` 仅把“状态为 pending、从未尝试”的旧积压标为 `skipped`，并写入固定迁移说明；不会触发 AI、剪辑或删除数据。

## 后果

- 运营点击“生成复盘”后若还需要成片，需在剪辑页面人工生成；新终稿的自动剪辑仍受 `CLIP_AUTO_GENERATE` 控制。
- 历史场次不会因部署或 Worker 重启突然产生大批 AI 成本和回放下载。
- API 暂时继续返回旧后处理字段，但前端不再把它展示为正在执行的业务步骤；后续可在单独版本中正式废弃字段。
