# ADR 0016：知识库问答流式输出与 UI 优化

**日期**：2026-07-24  
**状态**：已采纳  
**决策者**：lppmql

---

## 背景

知识库问答原来是一次性返回完整回答，用户需要等待 5-15 秒才能看到结果，体验像"卡住了"。需要改成 ChatGPT 式的打字机效果，逐字输出。

同时，对话页面存在以下问题：
- 流式打字时自动滚动到底部，用户无法阅读前面内容
- 用户消息没有时间戳，无法判断发送时间
- 等待检索时显示骨架屏，用户体验不够明确
- 推荐问题与"零食店避坑留资"业务不够贴切

## 方案对比

### SSE（Server-Sent Events）vs WebSocket

| 维度 | SSE | WebSocket |
|------|-----|-----------|
| 协议 | HTTP 单向（服务器→客户端） | 双向 |
| 实现复杂度 | FastAPI `StreamingResponse`，3 行代码 | 需要 `websockets` 库 + ASGI 中间件 |
| 浏览器兼容 | 所有现代浏览器 | 所有现代浏览器 |
| 适合场景 | 单向推送（AI 流式回答） | 双向实时通信 |

**选择 SSE**：知识库问答只需服务器推送 token 到前端，不需要双向通信。SSE 基于 HTTP，部署简单（不需要额外端口或协议升级）。

### 前端消费 SSE 方式

| 方式 | 优点 | 缺点 |
|------|------|------|
| `EventSource` API | 浏览器原生 | 只支持 GET 请求，不支持 POST |
| `fetch + ReadableStream` | 支持 POST + 自定义 header | 需要手动解析 SSE 行 |

**选择 fetch + ReadableStream**：因为需要 POST 发送问题内容和 JWT token。

## 技术细节

### 后端流式端点

```
POST /api/v1/ai/qa/stream
→ StreamingResponse(media_type="text/event-stream")
→ 每个 token 封装为 data: {"type":"token","content":"..."}
→ 结束发 data: {"type":"done","sources":[...]}
```

### Vue 响应式 Bug 修复

**问题**：直接操作 `aiMsg.content += token` 无法触发 Vue 重新渲染。

**原因**：`aiMsg` 是普通 JS 对象引用，不经过 `ref()` 的 Proxy 代理。

**解决**：通过 `messages.value.find(m => m.id === aiMsgId)` 获取响应式代理引用后再修改。

### 自动滚动策略

- **之前**：监听「消息数量 + 内容长度」，每次 token 都滚动
- **之后**：只监听「消息数量」，仅在新消息出现时滚动
- **效果**：流式打字中用户可自由阅读，不会被强制拉到底部
