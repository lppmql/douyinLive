# ADR 0032：ASR 行业热词启用与知识文档噪声过滤

- 日期：2026-07-30
- 状态：已采纳

## 背景

项目已经有两层关键词校准设计：

1. 识别前把行业热词传给 FunASR，提高品牌名和业务术语的识别概率。
2. 识别后使用精准纠错词典修正常见的一字误识别。

检查实际代码后发现，后处理纠错仍在工作，但 FunASR 启动消息中的
`hotwords` 被写死为空字符串，识别前增强没有真正启用。

同时，现有自动提取规则会把行业知识 Markdown 中的分隔线、面积数字和
括号说明当成热词，例如 `----------`、`150㎡`、`另设广州总部）`。
这些词会占用 200 个热词名额，并可能干扰识别。

## 备选方案

### 方案 A：清洗现有自动词库并恢复 FunASR 注入

继续以两份行业知识文档为真实来源，只解析明确的品牌分类，过滤说明文字，
再把结果注入直播中和下播后两种 FunASR 启动协议。

优点是改动小、立即生效，并继续复用现有后处理纠错。

缺点是词库优先级仍由代码维护，运营人员不能在页面上调整。

### 方案 B：建立分层词库

把词条按核心品牌、黑榜品牌、业务术语和地名分层，并为不同层设置权重与
纠错策略。

优点是准确率更容易持续优化。

缺点是需要新增词库配置格式和效果评估流程。

### 方案 C：建设关键词校准工作台

新增数据库和管理页面，支持维护标准词、常见误识别、启停状态和纠错记录。

优点是运营可以自行维护。

缺点是涉及前后端、权限和数据迁移，开发与维护成本最高。

## 最终决策

本次采用方案 A：

1. 直播中 `realtime` 和下播后 `offline` 的 FunASR 启动消息都加载同一份
   已清洗行业热词。
2. 品牌只从“一线、二线、三线、疑似快招、品牌、备注”等明确分类提取。
3. 品牌列表只在括号外的顿号处分割，避免把总部或门店说明拆成品牌。
4. 文档术语只接受人工确认的行业术语，不再使用贪婪正则截取整段文字。
5. 热词加载异常时降级为空热词继续转写，不让知识文档故障阻断整场任务。
6. 识别后的精准纠错继续保留，形成“识别前增强 + 识别后校正”的双层方案。

方案 B 和 C 留作后续迭代；在有真实误识别样本和准确率数据前不提前扩建。

## 影响范围

- `backend/app/services/asr/hotwords.py`：清洗品牌、地名和行业术语提取。
- `backend/app/services/asr/funasr_client.py`：恢复启动消息热词注入。
- `backend/tests/test_asr_hotwords.py`：验证核心词、噪声词和双协议握手。
- 不修改任务排序、分片断点、直播中/下播后协议选择和后处理纠错算法。

## 验收方式

1. `extract_hotwords()` 返回不超过 200 个热词。
2. 结果包含“好想来、赵一鸣、零食很忙、快招公司、回本周期”。
3. 结果不包含 Markdown 分隔线、预算数字、面积单位和括号说明。
4. `realtime` 与 `offline` 的启动消息均携带同一份非空热词。
5. ASR 相关回归测试、后端全量测试、前端类型检查和生产构建全部通过。
