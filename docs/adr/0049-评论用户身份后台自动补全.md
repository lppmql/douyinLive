# ADR 0049：评论用户身份后台自动补全

- 状态：已接受
- 日期：2026-09-01

## 背景

系统已经能够根据评论中的稳定 `sec_uid`，使用独立资料 Cookie 获取平台真实公开头像、自定义抖音号或数字短号。但此前只在人工执行全部数据刷新后自动触发，正常直播监控新增的评论用户仍需要在场次详情页点击“补全本场用户资料”。这与持续采集的使用方式不一致，也容易留下短期覆盖缺口。

## 决策

1. 应用启动时同步启动评论用户公开资料自动服务，每 60 秒发现一次未获取或缓存到期的用户，不依赖页面访问或人工按钮。
2. 自动模式每轮最多领取 `DOUYIN_PROFILE_BATCH_SIZE` 人，当前为 30 人；单人请求间隔、批次暂停、30 天缓存和失败退避继续复用现有规则。
3. 每轮访问平台前，先把数据库中已经验证的公开资料同步到回访用户的新评论副本；缓存命中的用户不重复访问平台。
4. 平台返回 403 或 429 时立即进入一小时全局冷却；单用户失败按 1 小时、6 小时、24 小时退避。冷却到期后由自动服务继续，不需要人工恢复。
5. 专用 Cookie 缺失、权限不安全或暂不可用时，自动服务保持待命，不调用平台接口，也不阻断评论、场次、ASR 或企业后台采集。
6. 应用停机时先取消自动发现循环和正在执行的资料请求，再关闭其他采集资源，避免后台 HTTP 请求遗留。
7. 场次详情只展示“后台自动获取”和全局执行进度，不再提供手动触发按钮。原有接口暂时保留用于兼容旧客户端和运维诊断。

## 结果

- 新评论用户会在后台自动获得平台真实公开资料，正常使用不再需要逐场点击。
- 自动处理速度受平台保护规则限制，不承诺新增用户立即完成；风控冷却期间页面继续展示已有真实数据。
- `sec_uid` 仍只作为平台稳定查询标识，绝不冒充公开抖音号；平台没有返回的头像或抖音号保持为空，不推测、不伪造。
