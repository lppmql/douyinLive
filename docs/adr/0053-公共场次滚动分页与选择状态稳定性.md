# ADR 0053：公共场次滚动分页与选择状态稳定性

- 状态：已接受
- 日期：2026-09-03
- 扩展：ADR 0046 的公共场次选择契约

## 背景

公共场次选择器最初只返回最新 50 场。真实业务库已有两千余场，默认列表只能覆盖最近几天；一次性返回全部场次又会增加接口响应、前端转换和下拉渲染成本。主播话术还会定时刷新 ASR 任务状态，导致场次选项对象变化，Naive UI 默认因此重置菜单滚动位置。

## 决策

1. 公共场次接口和剪辑候选接口保留原列表响应，并新增默认值为 0 的 `offset` 参数，保持旧调用方兼容。
2. 公共选择器每页请求 100 场，接近列表底部时继续加载；主播、日期或关键词变化后从第一页重新查询。
3. 各页面只负责把下一页数据转换为自己的 ViewModel，分页状态、并发保护和加载状态统一由公共 Hook 管理。
4. 追加结果按场次 ID 去重，保持后端按开播时间和场次 ID 倒序的稳定顺序。
5. 深链指定的旧场次只在第一页作为额外回显项，不挤占分页记录；后续页不重复强制插入。
6. 场次选项更新时保留菜单滚动状态，使 ASR 轮询和分页追加不会把用户带回列表顶部。

## 结果

- 用户无需一次性下载全部历史数据，也能连续浏览所有符合条件的场次。
- 主播话术、AI 复盘、AI 剪辑和知识库保持相同的分页与筛选行为。
- 接口仍返回数组，不要求旧客户端迁移响应结构；客户端是否继续翻页通过单页记录数判断。
- 当结果数恰好是页大小的整数倍时，客户端会多发一次空页请求来确认结束，这是保持接口兼容所接受的轻量代价。
