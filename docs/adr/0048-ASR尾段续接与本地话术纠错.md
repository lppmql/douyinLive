# ADR 0048：ASR 尾段续接与本地话术纠错

- 状态：已接受
- 日期：2026-08-31

## 背景

近期失败主要来自两类边界：直播刚结束时连续缓存不足完整的 120 秒窗口，以及直播流地址在识别过程中失效。旧流程会把已经写入话术的失败分片重新置为待处理，下一次执行又先删除该分片文字，造成尾段有效内容丢失。与此同时，离线终稿只有固定词典替换，无法利用上下文修正常见同音词。

本机同时运行 FunASR 和 9B 级 Ollama 模型。两个模型并发会明显争抢内存与算力，因此纠错不能进入实时或离线 ASR 的关键路径。

## 决策

1. 实时缓存不足但分片已经提交话术时，将该分片按实际读取时长封存为部分完成；已提交话术不删除，下一实时窗口从实际结束点继续。没有任何话术的失败分片仍按原重试规则处理。
2. 瞬时实时故障和离线失败按任务级上限自动续接，只重置失败分片；已经完成或部分完成的分片保持不动。
3. 本地模型纠错只处理已完成的离线终稿。任何排队或执行中的 ASR 任务都优先；ASR 到来时取消异步 Ollama 请求，已提交批次从数据库进度继续，未提交批次完整回滚。
4. 模型只能做保守同音词、品牌名和行业术语纠错。原始 FunASR 文本保存在 `raw_text_content`；返回 ID、阿拉伯数字、中文金额/数量/百分比/面积、地区、可靠词典术语、长度和文本相似度任一校验失败时，该段回退原文。
5. 复用现有 `postprocess_*` 持久化字段表达纠错状态，不新增表或数据库迁移；前端统一展示为“本地话术纠错”。

## 结果

- 下播尾段已经识别的真实话术不会因自动续接被删除。
- 本地模型失败、超时或被 ASR 抢占不影响终稿可用性，也不会把未提交进度误记为成功。
- 纠错会等待 ASR 队列完全空闲，因此完成时间不承诺实时；这是保护直播采集和转写速度的明确取舍。
- 若需回滚，可关闭 `ASR_LLM_CORRECTION_ENABLED` 停止新纠错；尾段封存和失败分片断点续接应保留，因为它们只减少丢字与重复识别。
