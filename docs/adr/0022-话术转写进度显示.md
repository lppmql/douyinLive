# ADR 0022：话术转写进度显示

**日期**：2026-07-25
**状态**：已实施

## 背景

话术转写页面的任务列表只显示状态标签（等待/处理中/完成/失败），用户不知道处理中的任务到底完成了多少。比如一场 10 分钟的直播要转写，用户只能看到「处理中」，不知道是刚开始还是快结束了。

实际上数据库里 `asr_audio_chunks` 表已经记录了每个任务被拆成几个音频分片、完成了几个，进度数据是现成的，只是没有传给前端。

## 决策

### 1. 进度以「音频分片」为粒度

**选择**：进度 = `completed_chunks / total_chunks`，而不是基于话术分段数。

**原因**：
- 音频分片是 Worker 处理的最小单元，每个分片对应一段 ffmpeg 取流 + FunASR 识别
- 话术分段数（`segment_count`）是识别结果的副产品，不能可靠反映进度
- Worker 按分片逐个处理，分片完成数天然就是进度

### 2. 后端批量查询，避免 N+1

**选择**：在 `list_transcription_tasks` 中先查出所有任务，再一次性 `GROUP BY` 查所有任务的分片统计。

```python
# 一次 SQL 查出所有任务的分片数，不是每任务一条 SQL
rows = db.query(
    AsrAudioChunk.task_id, AsrAudioChunk.status, func.count(AsrAudioChunk.id)
).filter(AsrAudioChunk.task_id.in_(task_ids)).group_by(AsrAudioChunk.task_id, AsrAudioChunk.status).all()
```

**原因**：
- 如果任务列表有 100 条，逐条查就是 100 次 SQL，接口响应会慢
- 一次批量查，无论多少任务，分片统计只查一次

### 3. 两处显示进度

**选择**：
- **状态卡片**：「正在转写」卡片上显示最快进度百分比（如「最快进度 45%」），不用打开抽屉就能看到
- **任务抽屉**：处理中的任务卡片上显示 `NProgress` 进度条，含「已完成/总分数（百分比）」

**原因**：
- 状态卡片给用户一个概览，知道有没有任务在跑、跑到哪了
- 抽屉给用户每个任务的具体进度，排查哪个任务快哪个任务慢

### 4. 进度只在 processing 状态显示

**选择**：`queued` 任务不显示进度（还没开始），`completed` 任务不显示（已经 100%），`failed` 任务不显示（没有进度的意义）。

**原因**：进度条对非处理中的任务没有意义，显示反而干扰。

## 替代方案（已拒绝）

### 方案 A：WebSocket 实时推送进度

**拒绝原因**：当前已有 5 秒轮询机制，WebSocket 增加复杂度但用户体验提升有限。进度不是秒级变化的（一个分片处理要几十秒到几分钟），5 秒轮询完全够用。

### 方案 B：在采集控制中心统一显示

**拒绝原因**：采集控制中心和话术页面是两个独立页面，用户可能在话术页面看结果时想了解当前转写进度，不应该要求他们切到采集页面。
