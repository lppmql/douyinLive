# ADR 0038：直播回放 AI 自动剪辑

- 日期：2026-08-07
- 状态：已采纳

> 2026-08-27 更新：云端模型与自动触发规则已被 [ADR 0044](0044-本地Ollama与人工AI剪辑.md) 取代，下文保留历史决策。

## 背景

直播回放是抖音零食店避坑留资直播的重要内容资产，但每场 1-2 小时的回放无法
直接用于短视频分发。需要把回放按主题自动切成 5 条可发布的竖屏短视频（含标题、
文案、话题），降低人工剪辑成本，放大直播内容的二次触达。

系统已有全部基础能力：句子级话术时间戳（`transcript_segments`，FunASR 分句）、
DeepSeek API、抖音回放 m3u8 采集（`stream_sources` + 请求头）、ffmpeg。

## 备选方案

### 方案 A：接入开源剪辑框架（FunClip / AutoCut）

FunClip（阿里，基于 FunASR）与项目同生态，AutoCut（OpenAI Whisper）是"保留句
即剪辑单"范式的鼻祖。但两者都需要自带 ASR 转写链路，与项目已有的 FunASR +
`transcript_segments` 数据模型重复；FunClip 还依赖 Gradio/moviepy/ImageMagick
生态，引入成本高于收益。

### 方案 B：纯自研薄层（采纳）

复用项目已有转写结果，只新增"LLM 选段 + ffmpeg 执行"两层：
- LLM 只做决策：从带时间戳的话术里挑主题片段、起标题写文案，输出 JSON 契约；
- 程序只做执行：按行号映射回真实时间戳，ffmpeg 精确切割、竖屏转换、烧录字幕、
  拼接、生成封面。

不引入任何新剪辑框架，全部复用现有栈（DeepSeek + ffmpeg + 现有任务队列）。

## 最终决策

1. **数据模型**：新增 `clip_clips` 表（成片：标题/文案/话题/片段时间轴/视频路径/
   封面/状态 draft·approved·discarded）；生成任务复用 `scraper_tasks`
   （`task_type="clip_task"`，自带进度、重试、取消，挂进 `collector_task_control`
   单执行器队列，ffmpeg 天然单并发）。
2. **选段契约（防幻觉）**：输入话术按 `[行号] 开始秒-结束秒|类型|文本` 组织；
   DeepSeek 只输出行号引用（`segments: [{index}]`），程序端映射回真实时间戳。
   实测推理模型会"合理偏移"时间戳导致 5/5 校验失败，行号契约后全部通过；
   时间戳容差匹配仅作兜底。单方案 1-3 段、总时长 30-90 秒、重叠拒绝、超长话术
   按时间均匀抽样压缩。
3. **一次调用出 5 方案**：每场自动任务仅 1 次 DeepSeek 调用（5 条方案一起出），
   手动重剪 1 次调用；`max_tokens` 提高至 12000（推理模型会先消耗 reasoning
   token，默认 4096 会输出空内容）。
4. **回放素材**：剪辑前按需从 `stream_sources` 下载完整回放到
   `data/videos/<session_id>/replay.mp4`（流拷贝不重编码，幂等复用）；流地址过期
   时复用 `refresh_session_stream_url`（已保存 Cookie 抓新地址）重试一次。
5. **剪辑管线（每片段一次重编码，最后无损拼接）**：
   `-ss` 前置精确切割 → `scale/crop` 转竖屏 1080x1920 → `subtitles` 烧录 ASS
   大字幕（该片段独立 0 起时间轴）→ concat demuxer 流拷贝拼接 → 首帧封面。
   字幕烧录依赖带 libass 的 ffmpeg：优先项目内 `.runtime/ffmpeg/ffmpeg`
   （evermeet.cx 静态版 9.0），可 `CLIP_FFMPEG_BIN` 覆盖，缺失时明确报错。
6. **字幕**：ASR 文本无标点，按 13 字/行切分、字符比例分配时间（0.8-3.5s 窗口），
   白色大字 + 黑描边 + 底部安全区样式。
7. **自动触发**：离线终稿后处理链完成（`process_session_post_collection`）且
   `CLIP_AUTO_GENERATE=true`、场次有回放源时自动入队；页面可手动整场生成/单条
   重剪（可填选题方向 user_hint）。
8. **只生成内容，不自动发布**：确认（approved）后的成片由运营复制标题/文案/话题
   人工发布到抖音，规避开放平台授权与风控成本；数据库预留状态位，将来可接
   自动发布。

## 影响范围

- 新增：`clip_clips` 表、`services/clips/`（选段/校验/下载/字幕/渲染/编排）、
  `/api/v1/clip/*` 12 个接口、前端一级菜单「AI自动剪辑」页面、`.runtime/ffmpeg/`
  静态版 ffmpeg。
- 复用不改：`collector_task_control`（仅注册新 task_type）、`stream_refresh`、
  `stream_sources`、DeepSeek 客户端、elegant-router 菜单机制。
- 存储：每场回放约 1-4GB（`data/videos/`，已被 .gitignore 覆盖），成片每条约
  10-12MB。

## 验收方式

1. 真实场次 #2130（81 分钟回放）全链路跑通：AI 选段 5/5 校验通过、回放下载
   3.7GB、5 条竖屏成片渲染成功（1080x1920 H.264+AAC，30-90 秒，含字幕与封面）。
2. 编造时间戳、超时长、重叠片段被校验拦截；AI 输出空内容自动重试。
3. API 12 接口 + 媒体 Cookie 白名单（浏览器原生 video 直播放）。
4. 后端 383 项测试、前端 typecheck/Lint/Build、完整 `make check` 通过。
