# ADR 0035：评论用户客资精确匹配与钩子时间窗归因

- 日期：2026-08-01
- 状态：已采用

## 背景

直播详情已有评论、主播转写、分钟指标和客资，但缺少用户级聚合与可追溯转化分析。评论中的 `sec_uid` 是平台稳定标识，不是公开抖音号；客资接口主要提供公开抖音号、主播和提交时间。错误混用这些字段会把客资标给错误用户。

## 决策

1. 评论用户按 `sec_uid` 聚合展示，但只有评论公开抖音号与客资 `douyinId` 归一化后完全一致，才标记“已留资”。昵称、`sec_uid` 和时间接近均不能作为用户级确认依据。
2. 用户“已留资”和本场客资统计只使用客资同步流程已经明确归属到本场的数据；未归属记录即使主播名、时间接近也不进入确认态。
3. 主播钩子只从已完成的真实 ASR 片段识别，相邻 30 秒的连续片段合并为一次动作。
4. 一条客资只关联其提交前最近一次且不超过 30 分钟的钩子，并在接口和页面明确标注“时间窗关联，不代表确定因果”。
5. 平台未返回头像或公开抖音号时保持为空，页面展示字段覆盖率，不推测或伪造身份。
6. 分析结果由详情接口实时组合，最多分析最近 2000 条评论、每位用户最多返回 50 条评论证据，避免长直播产生无界响应；接口同时返回整场评论总数、实际分析数和截断状态，页面明确标注样本范围。
7. 钩子按“具体资料、领取动作、资料价值”三要素分级；后台、私信、发消息、发资料、领取和红色按钮等属于明确转化动作。只介绍资料但没有动作时标记为“钩子铺垫”，不计入正式钩子次数。
8. 钩子、铺垫、评论、主播话术、指标、告警和复盘发现进入同一条可回放时间轴；不再维护重复的独立钩子时间轴。
9. 企业评论接口只提供 `sec_uid` 时，使用独立的评论用户资料 Cookie 与固定请求指纹低速查询公开资料；该凭据不复用企业后台采集账号，并只保存在 Git 忽略的本地文件。
10. 公开资料按 `sec_uid` 全局缓存，优先补全高意向与最近评论用户；成功缓存30天，失败递增退避，遇到403、429或连续失败自动暂停。
11. 用户级客资精确匹配分别检查 `unique_id` 和 `short_id`，任一与客资 `douyinId` 归一化后完全一致即可确认，同时保存并展示实际匹配类型。

## 影响

- 直播场次详情公共接口新增转化摘要、钩子事件、评论用户分析和身份覆盖字段。
- 页面新增钩子时间轴、用户留资状态、主播承接证据、未留资建议和全部场次指标。
- 统一时间轴可筛选转化钩子，并展示强弱、缺失要素以及钩子后 5/15/30 分钟真实评论与客资变化。
- 身份补全仍受非官方公开资料接口稳定性和平台风控限制；系统不得绕过验证码或在阻断后继续高频请求。
- 独立 Cookie 失效时需要重新导出本机凭据；Cookie 不进入 Git、日志、前端或业务数据库。
