# ADR 0046：公共场次选择与知识库单场检索

- 日期：2026-08-29
- 状态：已采纳（用户确认方案 A）

## 背景

主播话术、AI 复盘和 AI 剪辑各自实现了场次下拉，显示字段、加载数量和搜索方式不同。剪辑页只加载最近候选场次，如果在前端对这部分数据做主播或日期过滤，会漏掉数据库中真实存在的历史场次。

知识库页面虽然能从 URL 读取 `sessionId`，但旧实现主要把“只结合某场”拼进用户问题，再依靠文本解析缩小关键词检索范围；对话本身没有保存场次归属，重新打开历史对话时也无法可靠恢复检索边界。

## 决策

1. 新增公共 `SessionSelector` 业务组件，统一主播筛选、日期范围、远程场次搜索、主播身份和场次元信息展示。话术、复盘、剪辑和知识库四个页面共同使用；页面自己的操作按钮和业务状态继续留在各自模块。
2. 主播筛选项来自数据库中真实场次的最新身份快照，不从当前 50 条候选临时推导。筛选身份键依次使用稳定的 `douyin_uid`、抖音号；两者都缺失时才使用“`room_id` + 规范化主播名称/昵称”的明确快照后备键，同一直播间的轮班主播不会被合并，完全缺少主播身份的脏快照不生成选项。日期按数据库中的北京时间 `live_start_time` 筛选，范围包含开始日和结束日；前端“今天/昨天”也显式以上海时区生成日历日期。
3. 新增公共场次候选接口，支持场次编号、标题、主播名称、昵称和抖音号远程搜索。URL 指定的旧场次即使不在当前前 50 条中也保证回显。
4. 剪辑候选接口复用相同的主播、日期和关键词条件，但继续保留“已结束且详情完整”的业务门槛及话术、成片统计，不把所有页面强制为相同候选范围。
5. 知识库保留“全部场次”模式。选择具体场次后，`session_id` 作为正式请求字段进入关键词检索、Qdrant 向量过滤和 MySQL 结果补齐；程序最终仍按 MySQL 场次字段校验结果，不能只依赖提示词。
6. 知识条目向量新增 `session_id` payload。已有旧向量没有该字段时不会进入单场向量结果，关键词检索和已有时间片向量继续兜底；知识再次同步时会按新格式更新向量，不伪造历史归属。
7. 知识库对话增加可空 `session_id`。空值表示全知识库，历史对话保持空值，不根据旧回答猜测归属；单场对话重新打开时恢复原场次。人工切换范围会新开对话但保留旧对话记录，避免跨场上下文混用。
8. 公共远程筛选、历史对话详情和知识库流式回答均使用请求代次校验；流式请求同时传入 `AbortSignal`。慢返回的旧请求不得覆盖新筛选、新对话或新场次，主播选项接口失败时降级为空列表而不阻断核心场次加载。

## 数据与兼容

Alembic `g8c9d0e1f2a3` 为 `conversations` 增加可空外键和索引，删除场次时使用 `SET NULL` 保留对话内容。接口新增字段均为可选；未选择场次时知识库行为与原全局问答兼容。

公共组件不新增第三方依赖，复用 Vue 3、Naive UI、`AnchorIdentity`、VueUse 防抖和现有 URL 场次联动。

## 验收

- 主播、日期、关键词组合筛选只返回真实匹配场次，日期包含首尾两日，反向日期范围被拒绝。
- 话术、复盘、剪辑、知识库均使用公共组件；剪辑仍只展示原有可剪辑候选。
- 深链接旧场次可回显，切换页面或刷新后保留 `sessionId`。
- 单场知识问答的关键词、向量和最终来源均不能跨场；历史对话恢复原场次，全局对话保持全知识库。
- 快速连续修改筛选、切换历史对话或切换知识库范围时，旧响应不覆盖当前状态；停止生成会真正取消浏览器流请求。
- 执行完整 `make check`，覆盖后端、前端类型与 Lint、生产构建、Alembic 和 Docker 配置。
