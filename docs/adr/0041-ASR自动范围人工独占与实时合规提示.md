# ADR 0041：ASR 自动范围、人工独占与实时合规提示

- 日期：2026-08-18
- 状态：已采纳
- 关联：ADR 0024、0033、0037

## 背景

现有 ASR 队列只区分直播/离线通道，并按最新场次优先。历史下播场次会继续进入自动
队列，运营手动选择某一场时也不能抢占当前长任务；主播话术页只显示最后一条实时预览，
场次详情依赖轮询，合规规则要到复盘生成后才可见。

## 备选方案

### 方案一：只在前端重排任务

实现快，但 Worker 不识别人工优先和日期范围，刷新页面或重启后会失效。

### 方案二：数据库持久化调度策略，Worker 在分片边界让出（采纳）

把排队来源和排序策略作为后端契约。人工任务绝对优先，其他任务在两分钟分片边界保存
断点并暂停；实时结果通过现有 WebSocket 同时写入两个页面。

### 方案三：引入独立消息队列和抢占式进程终止

可实现秒级抢占，但会增加部署复杂度，并可能破坏当前分片或丢失已识别内容。

## 最终决策

1. 自动范围固定为 `Asia/Shanghai` 自然日：所有正在直播场次，以及当天已下播场次。
   历史场次只能由运营手动选择。
2. `asr_tasks.queue_source` 区分 `auto/manual`。同一时刻最多一条活动人工任务；新的人工
   选择覆盖旧选择，自动任务在分片安全边界变回排队状态并保留完成分片。
3. `asr_dispatch_policies` 保存单例排序：`smart`、`latest`、`fifo`。三种排序都不能越过
   人工任务和直播场次的硬优先级。
4. 实时 ASR WebSocket 返回已落库片段 ID、时间、文本和关键词风险提示。主播话术页与
   场次详情统一时间轴直接 upsert，不等待轮询。
5. 合规关键词复用 `compliance_rules`，结果统一标为“涉嫌违规、待人工复核”，不输出
   确定违法结论；REST、WebSocket 和复盘工作台使用同一匹配函数。
6. Worker 必须每轮写入独立心跳；只有 FunASR 引擎可用、Worker 进程存在且心跳新鲜时，
   页面才显示“转写服务正常”。持续服务发现僵死 Worker 后先清理残留进程再自动拉起，
   所有处理中分片按断点恢复，不因 PID 尚在而误报健康。
7. 任务中心提供安全停止、断点重试和取消人工优先。安全停止只在分片边界生效并保留
   已完成内容；取消人工优先不会取消当前任务，只把它放回自动队列。

## 数据与接口影响

- Alembic `d5e6f7a8b9c0`：新增 `asr_tasks.queue_source` 和 `asr_dispatch_policies`。
- 新增 `GET/PUT /api/v1/transcripts/dispatch-policy`。
- 新增任务级 `stop`、`retry` 和 `release-priority` 接口；任务明细返回真实排队位次与
  停止请求状态，任务汇总单独统计暂停项。
- ASR 控制状态新增 Worker 心跳健康度、状态、时间与心跳年龄。
- `POST /api/v1/transcripts/{session_id}/queue` 明确为人工独占排队。
- 话术分段及实时消息新增 `compliance_hits`。

## 验收方式

1. 昨日下播场次不自动入队，今日下播和所有直播中场次会自动入队。
2. 人工选择历史场次后，其他任务在当前分片结束时暂停，人工任务完成后自动恢复。
3. 三种自动排序可切换，直播中任务仍始终优先。
4. 实时片段无需刷新即可出现在主播话术页和直播详情统一时间轴。
5. 命中规则时显示关键词、规则与建议，并明确要求人工复核。
6. 模拟 Worker 有进程但心跳超时后，系统自动替换进程；页面明确提示恢复状态，任务从
   已完成分片之后继续。
7. 任务抽屉能显示人工阻塞原因、真实排队位次，并能安全停止、断点重试或取消人工优先。
