# ADR 0030：轻量文档治理与维护入口修复

- 日期：2026-07-29
- 状态：已采纳

## 背景

项目已经有 README、开发指南、部署指南、故障排查、前端组件规范、验收文档和 20 多篇 ADR。文档不是缺少，而是入口开始变多：

- README 指向的新手教程文件不存在。
- 架构说明里的 ADR 导航只列到 0013，但实际已经写到 0026。
- `.env.example` 章节编号重复，排查配置时容易误读。
- 开发指南写死了路由、模型和迁移数量，代码增长后这些数字会变旧。
- 验收文档写得清楚，但还缺少“改了哪个模块就跑哪份验收”的映射。

## 备选方案

### 方案 A：轻量治理（采用）

- 补齐新手上手指南。
- 新增 ADR 总索引，并让架构说明只链接总索引。
- 修正 `.env.example` 章节编号。
- 删除开发指南里容易过期的数量。
- 在验收说明中新增改动类型和必跑验收的映射。

优点是改动小、风险低，能立刻降低后期维护成本。

### 方案 B：中度治理

在方案 A 基础上新增 `CONTEXT.md`，统一项目术语。优点是更利于长期协作，缺点是需要一次专门的领域建模，当前不是最急。

### 方案 C：完整治理

把 `AGENTS.md`、`CLAUDE.md`、开发指南中的流程规则合并成维护手册。优点是入口最统一，缺点是改动范围更大，需要额外确认每条规则的优先级。

## 决策

采用方案 A。

这次只修入口和导航，不改变产品功能、不调整开发流程强约束、不删除旧 ADR。

## 影响

- 新人可以从 README 进入真实存在的新手指南。
- 查架构决策时先看 ADR 总索引，不再依赖手写长列表。
- 配置模板编号连续，后期排查更直观。
- 开发指南不再写死容易过期的统计数字。
- 改代码后能按模块找到对应验收文档。

## 验收方式

1. README 的新手指南链接可以打开。
2. 架构说明可以跳转到 ADR 总索引。
3. ADR 总索引包含 0001 到 0030 的所有 ADR。
4. `.env.example` 章节编号连续。
5. 验收说明能根据改动模块找到对应验收文档。
