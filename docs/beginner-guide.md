# 新手上手指南

这份指南只解决一个问题：第一次接手项目时，先按什么顺序做，才能少走弯路。

## 1. 准备本地配置

在项目根目录执行：

```bash
cp .env.example .env
```

然后打开 `.env`，至少填写这些值。AI 使用电脑上的 Ollama，不需要购买或填写云端 API Key：

```text
JWT_SECRET_KEY          登录令牌密钥，至少 32 位随机字符串
DB_PASSWORD             MySQL 密码，建议至少 16 位随机字符串
REDIS_PASSWORD          Redis 密码，要和 REDIS_URL 里的密码一致
```

首次使用 AI 前先打开 Ollama 应用，再执行 `./scripts/setup_ollama_model.sh`。脚本会下载官方 `qwen3.5:9b`，并创建支持 64K 长话术的项目模型 `douyin-live-qwen`。模型文件约占 7GB，只在本机运行。

## 2. 首次安装与日常启动

从项目根目录执行：

```bash
./setup.sh
# 按脚本提示填写 .env 后：
./start.sh standard
```

启动后打开：

| 页面 | 地址 | 用途 |
|---|---|---|
| 前端页面 | http://localhost:9527 | 日常操作入口 |
| 后端 API 文档 | http://localhost:8000/docs | 查看接口是否存在、请求字段是什么 |
| 健康检查 | http://localhost:8000/health | 快速确认后端是否正常 |

如果启动失败，先跑：

```bash
make doctor
```

`doctor` 的意思是“环境体检”，会检查 Docker、Python、Node、ffmpeg、数据库和常见弱配置。

`setup.sh` 只在新电脑首次部署或依赖版本升级时运行；`start.sh` 不再临时下载大体积依赖。
日常模式分为 `lite` 和 `standard`（推荐）；`lite` 不自动启动 FunASR，适合临时查看数据或低资源电脑。

## 3. 首次登录和采集账号

1. 打开 http://localhost:9527。
2. 使用初始化管理员账号登录。账号和密码来自 `.env` 里的 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD`。
3. 进入数据采集页面。
4. 添加或检查抖音采集账号。
5. 确认页面显示 Cookie 有效、浏览器指纹已保存。

Cookie 的大白话解释：它是浏览器保存的登录凭证。浏览器指纹是系统模拟真实浏览器环境的一组参数。两者一起用，系统才能稳定访问已授权的抖音后台数据。

## 4. 第一次跑真实数据

建议按这个顺序验证：

1. 在采集页点击检查 Cookie。
2. 执行一次全部场次数据补齐刷新。
3. 打开直播场次列表，确认有真实场次。
4. 选择一场已结束且有回放的场次，创建话术转写任务。
5. 等后台知识库自动同步。
6. 到知识库页面问一个和该场直播相关的问题，检查引用来源。

项目规则要求使用真实数据。没有真实账号、真实场次或真实回放时，不要为了“看起来成功”手写假数据。

## 6. 每次改完最少做什么

不再每次都跑完整测试和构建。先按改动范围选一档，从项目根目录执行：

```bash
# 只改普通说明文档、注释或提示文案
make check-docs

# 只改一个后端模块：把测试路径换成实际相关测试
make check-backend TESTS="tests/test_local_llm_client.py"

# 只改一个前端模块：把路径换成实际改动文件
make check-frontend FILES="src/views/home/index.vue"

# 改数据库、安全、依赖、构建配置、公共接口、跨模块、CI 等高风险内容
make check
```

上面四条是不同选择，不是顺序执行。小改动不默认启动浏览器、真实 AI 推理或长音频转写；具体边界见[开发指南的提交前检查](开发.md#5-提交前检查)。全量检查仍保留 45% 后端覆盖率门槛。

GitHub 上普通说明文档只跑轻检查，代码或配置仍跑全量。注意：`docs/行业知识/` 是程序真正读取的知识数据，不能按普通文档跳过。

如果改了数据库模型，需要先生成并人工确认迁移，再应用迁移后运行全量检查：

```bash
cd backend
source .venv/bin/activate
alembic upgrade head
```

数据库迁移的大白话解释：迁移就是“把数据库表结构从旧版本安全改到新版本”的脚本。不要直接手动改线上表结构，否则以后很难知道数据库到底变过什么。
