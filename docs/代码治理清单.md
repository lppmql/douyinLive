# 代码治理清单

状态：常用
维护人：项目维护
最后更新：2026-07-29

这份清单用来记录“以后哪些代码值得整理”。它不是一次性重构计划，不要一口气全改。

模块的大白话解释：模块就是“别人怎么用它”和“它内部怎么做”分开的东西。好模块应该让别人学很少入口，就能用到很多能力。

## 治理原则

1. 一次只整理一个明确模块。
2. 先补测试或确认现有测试能覆盖，再拆代码。
3. 不为了行数好看而拆；只有能让调用更简单、修改更集中，才值得拆。
4. 后端接口文件只处理请求和响应，复杂业务放到服务模块。
5. 前端大页面优先拆成展示组件、状态 composable、数据 adapter、工具 helper。

## 建议执行顺序

1. 先整理知识库前端 `ChatPanel.vue`，因为它和最近修复最相关。
2. 再整理知识库后端 `kb_service.py`，减少问答逻辑扩散。
3. 再处理采集浏览器链路，避免 Cookie、指纹和恢复逻辑散落。
4. 最后处理客资同步和话术工作台。

每一步都要单独提交，方便回滚。
